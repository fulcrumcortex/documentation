Chat supports one non-empty attachment at a time, up to 20 MB. Supported families include Office documents, images, PDF, text, Markdown, CSV, JSON and supported audio. A recognised extension and a useful analysis result are separate concerns.

Before you start

The active composer determines where text, mentions and attachments will be sent. A private assistant panel can sit beside a shared conversation, so check the heading as well as the visible text. Inspect the file or recording before sending it; a local preview is not a completed upload. Chat validates a single attachment and rejects empty, oversized or unsupported files. Receipt state describes the message transport, not the success of a task requested inside it. If the result is uncertain, inspect the existing conversation and any external destination before retrying. This is especially important when a message asks the assistant to send, book or create something.

Step-by-step

  1. Select Add attachment in the intended composer.
  2. Choose one supported file and inspect its preview, name and any validation message.
  3. Add a question explaining what to do with it and submit when the attachment is correct.

What the settings mean

Control or stateMeaning
ComposerThe current destination for text and pending media.
PreviewContent selected locally and still awaiting the send action.
ReceiptSending, failed, sent, delivered or read information.
Task resultThe separate artifact or external action requested in the message.

Check the result

The correct file is attached once to the intended conversation.

If it does not work

If rejected, check size, file type and whether more than one file was selected. Renaming an unsupported file extension does not make its contents supported.
