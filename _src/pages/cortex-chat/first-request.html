A useful brief gives the assistant an observable outcome, the source material and the actions you authorise. For example, reviewing an enquiry and drafting a reply is different from sending that reply. The tools available to the Sidekick still limit what it can do.

Before you start

Check three separate layers: the identity signed in through Fmail, the Sessions workspace supplying the Sidekick, and the app connection supplying the requested data. One working layer does not prove the others are ready. Start with a harmless read or a draft before asking for an external change. A message to an assistant can contain instructions and source material, but permissions come from the saved account and tool settings. When an operation is unclear, describe the required outcome and ask the assistant to identify the missing stage instead of changing several settings at once.

Step-by-step

  1. Choose a connected Sidekick and describe one concrete outcome.
  2. Include the relevant record or supplied context and any constraints.
  3. State what counts as finished, such as a draft, a saved document or an authorised send with evidence.

What the settings mean

Control or stateMeaning
AccountWho is signed in and which personal or company context is being used.
SidekickThe selected assistant and its runtime availability.
ApplicationThe connected service and the account it uses.
OutcomeThe artifact or destination record that establishes completion.

Check the result

The reply addresses the intended result and clearly identifies any missing input or action that remains.

If it does not work

If the result is vague, supply the trigger and expected behaviour rather than asking the assistant to do everything. A stronger brief cannot fix a missing tool connection by itself.
